# Project: LinkedIn Resume — Infographic Web App

## Project Overview

An infographic-style resume site, built/generated with Claude Code. Two parts:
- `/web`: Next.js (TypeScript) frontend, deployed to Vercel at bidamia.ca. This is the actual site.
- Python pipeline (`/src/linkedin_project`, `/scripts`): scrapes LinkedIn, cleans/normalizes the data, and exports it to `web/src/data/resume.json`, which the frontend reads statically at build time. There is no Python runtime in production — the Python side only produces data.

## Important
1. Before you make any change, create and checkout a feature branch named "feature_some_short_name". Make and then commit your changes in this branch.
2. You must write automated tests for all code.
3. You must compile the code and pass ALL tests before committing.
4. Code Reviews: Submit a pull request for code reviews before merging into the main branch.
5. Install all python libraries to the virtual environment

## Development Standards
- **Language**: Python 3.10.12
- **Code Style**: Follow PEP 8 strictly, use Black for formatting
- **Type Hints**: Required for all function signatures and class definitions
- **Documentation**: Docstrings required for all public functions and classes

## Workflow Requirements
1. Create feature branch: `feature-datapipeline-[description]` or `feature-visualization-[description]`
2. Write unit tests for all data processing functions
3. Run `pytest` and ensure all tests pass
4. Run `black .` and `flake8` before committing
5. Update relevant documentation in `/docs` if adding new features

##Project Structure
- `/web`: Next.js (TypeScript + Tailwind) frontend — the deployed site, built for Vercel
- `/web/src/app`: App Router pages and layout
- `/web/src/components`: Infographic sections and chart components (hand-rolled SVG where possible, see `mccandless-infobeauty` skill for the visual language)
- `/web/src/data/resume.json`: Static resume data consumed at build time — generated by `scripts/export_resume_json.py`, not edited by hand
- `/src/linkedin_project`: Main Python package containing the data pipeline
- `/src/linkedin_project/scrape`: Code responsible for collecting LinkedIn profile data
- `/src/linkedin_project/transform`: Data cleaning, normalization, and transformation logic
- `/src/linkedin_project/storage`: Data persistence logic including DuckDB interactions
- `/src/linkedin_project/pipelines`: Pipeline orchestration, including `export_resume.py` (DuckDB → plain Python data, falls back to sample data)
- `/src/linkedin_project/utils`: Shared helper functions used across modules
- `/data`: Local project data directory
- `/data/raw`: Raw scraped or ingested data snapshots
- `/data/interim`: Intermediate datasets produced during cleaning or transformation
- `/data/processed`: Final cleaned datasets
- `/data/duckdb`: DuckDB database files used for querying and analytics
- `/scripts`: Command-line scripts used to run scraping, transformation, or the full pipeline, including `export_resume_json.py` which writes `web/src/data/resume.json`
- `/tests`: Unit and integration tests for the Python pipeline
- `/.github/workflows`: GitHub Actions workflows for CI (Python pipeline) — Vercel handles frontend build/deploy on push via its own GitHub integration
- `/docs`: Project documentation such as architecture notes and data models

## Data Handling Standards
- Use Pandas for data manipulation, prefer vectorized operations
- All data files must be documented in `/data/README.md`
- Never commit raw data files to version control
- Use environment variables for database connections and API keys


## Dependencies
- Python pipeline — Core: pandas, numpy; Data: duckdb; Scraping: playwright, beautifulsoup4; Testing: pytest, pytest-cov
- Frontend (`/web`) — Next.js, React, TypeScript, Tailwind CSS; no chart library by default, prefer hand-rolled SVG per [[mccandless-infobeauty]] unless a chart genuinely needs one
