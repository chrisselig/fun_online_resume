# Architecture

## Overview

This project exports hand-curated resume content as static JSON, consumed by a Next.js infographic resume site deployed to Vercel. The Python side only ever produces data — there is no scraper, no database, and no Python runtime in production.

## Data Flow

```
/src/linkedin_project/pipelines/export_resume.py  ← hand-curated resume content
      │
      ▼
/scripts/export_resume_json.py   ← writes web/src/data/resume.json
      │
      ▼
/web/                             ← Next.js infographic site, built + deployed by Vercel
```

## Key Layers

| Layer | Location | Responsibility |
|-------|----------|----------------|
| Pipeline | `/src/linkedin_project/pipelines/export_resume.py` | All resume content (profile, experience, skills, education, portfolio) as plain Python data structures — the single source of truth |
| Frontend | `/web/` | Next.js (TypeScript + Tailwind) infographic site — reads `src/data/resume.json` at build time, no runtime data fetching |
| Utils | `/src/linkedin_project/utils/` | Shared helpers |

## Updating resume content

Edit `export_resume.py` directly, then regenerate the JSON:

```bash
python scripts/export_resume_json.py
```

Commit the updated `web/src/data/resume.json` alongside the Python change.

## Frontend

The Next.js app (`/web`) renders the resume as a series of infographic sections (`src/components/`) plus a handful of bonus arcade mini-games built from the same real data (`src/components/Arcade*.tsx`). Visual language varies by design branch — see the component styling directly, or the `mccandless-infobeauty` skill for the design principles behind the original infographic direction.

Data is static: `src/data/resume.json` is generated by `scripts/export_resume_json.py` and imported directly at build time — no API route, no client-side fetch.
