# Architecture

## Overview

This project scrapes LinkedIn profile data, transforms it, and exports it as static JSON consumed by a Next.js infographic resume site deployed to Vercel. The Python side only ever produces data — there is no Python runtime in production.

## Data Flow

```
LinkedIn Profile
      │
      ▼
/src/linkedin_project/scrape/    ← raw data collection
      │
      ▼
/data/raw/                       ← raw snapshots stored here
      │
      ▼
/src/linkedin_project/transform/ ← cleaning, normalization
      │
      ▼
/data/processed/                 ← final datasets
      │
      ▼
/src/linkedin_project/storage/   ← DuckDB persistence layer
      │
      ▼
/data/duckdb/                    ← DuckDB database files
      │
      ▼
/src/linkedin_project/pipelines/export_resume.py  ← DuckDB → plain Python (sample-data fallback)
      │
      ▼
/scripts/export_resume_json.py   ← writes web/src/data/resume.json
      │
      ▼
/web/                             ← Next.js infographic site, built + deployed by Vercel
```

## Key Layers

| Layer | Location | Responsibility |
|-------|----------|----------------|
| Scrape | `/src/linkedin_project/scrape/` | Headless Chromium (Playwright) — logs in to LinkedIn and scrapes profile sections via DOM selectors |
| Transform | `/src/linkedin_project/transform/` | Clean and normalize data; vectorized pandas operations |
| Storage | `/src/linkedin_project/storage/` | DuckDB read/write with parameterized queries |
| Pipelines | `/src/linkedin_project/pipelines/` | Orchestrate scrape → transform → load → export to JSON |
| Frontend | `/web/` | Next.js (TypeScript + Tailwind) infographic site — reads `src/data/resume.json` at build time, no runtime data fetching |
| Utils | `/src/linkedin_project/utils/` | Shared helpers |

## Scraper

The scraper (`src/linkedin_project/scrape/scraper.py`) uses Playwright's `sync_api` to drive a headless Chromium browser:

1. Navigates to `https://www.linkedin.com/login` and submits credentials
2. Detects auth challenges (checkpoint/verification) and raises `AuthError`
3. Loads the target profile URL, scrolls to trigger lazy content, and clicks "Show all" links
4. Extracts experience, education, skills, and certifications via CSS selectors
5. Returns a `ProfileData` dataclass containing one pandas DataFrame per section

Run via `scripts/scrape_linkedin.py`. Set `HEADLESS=false` to watch the browser.

## Frontend

The Next.js app (`/web`) renders the resume as a series of infographic sections (`src/components/`), styled per the visual language captured in the `mccandless-infobeauty` skill: restrained 2-hue palette (navy + amber accent on a warm neutral background), bold typography-driven hierarchy, and hand-rolled SVG charts instead of a charting library (e.g. `src/lib/circlePack.ts` — a deterministic circle-packing layout for the skills section, sized by endorsement count).

Data is static: `src/data/resume.json` is generated by `scripts/export_resume_json.py` and imported directly at build time — no API route, no client-side fetch.

## Database

DuckDB is used as the local analytical database. Files are stored in `/data/duckdb/linkedin.db`. Never commit `.duckdb` files to version control.
